εθ(t)(xt) — four symbols, zero multiplications

The confusion this page dissolves: reading the parentheses in εθ(t)(xt) as “…times xt”. They are function application — xt is the input, exactly like the x in f(x). Three tabs: the symbol exploded piece by piece, the wrong reading actually executed (watch it destroy the image), and the two-step path from symbol to code.

ε — the functionThe noise predictor itself: the trained U-Net. A machine that eats an image and spits out its noise estimate.
θ — subscript: the weightsThe learned parameters. “This particular trained model” — in code, the loaded checkpoint behind model.
(t) — superscript: which timestepConditions the prediction on the noise level. In code it’s simply the second argument: model(x_t, t).
(xt) — THE INPUTParentheses of function application, not multiplication. The noisy image goes into the machine — the first argument: model(x_t, t).
Same grammar you already know
NOTATIONMEANINGNOT

εθ(t)(xt)Noise predictor at timestep t, applied to xtε · θ · t · xt
If it were multiplication, the math would break. So let’s run it.
t500
❌ WRONG reading — treat (xt) as a multiplication
x_0_hat = (x_t - bbar_t.sqrt() * noise * x_t) / abar_t.sqrt()
✅ CORRECT reading — noise already IS εθ(t)(xt)
x_0_hat = (x_t - bbar_t.sqrt() * noise) / abar_t.sqrt()
🔬 Why the wrong one shreds the image: multiplying noise by x_t scales every pixel by a random factor before subtracting — the reconstruction divides by √ᾱt and amplifies the damage. The correct line subtracts the model’s prediction once, as the formula says, and the shirt comes back. Drag t high and watch the gap explode.
