Why @inplace? A missing return silently breaks the pipeline

Both functions modify b correctly — only one gives it back.

WITHOUT @inplace

def f(b):
    b['image'] = [to_tensor(o) ...]
    # forgot to return b!
return value: —

WITH @inplace

@inplace
def f(b):
    b['image'] = [to_tensor(o) ...]

# decorator builds:
def _f(b):
    f(b)
    return b
return value: —

In Python, a function with no return evaluates to None. HuggingFace's .with_transform keeps the return value of your transform, so a transform that mutates b but forgets return b hands back None — the sample is destroyed. Rather than remember return b in every transform, inplace is a decorator that wraps your function to call it and then return its argument: @inplace adds the return b for you.
