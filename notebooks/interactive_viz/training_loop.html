loss over iterations

PyTorch accumulates into .grad on purpose (it enables gradient accumulation tricks for huge models). But in a normal loop, skipping step 5 means each update uses the sum of every gradient so far — stale gradients keep pushing the weight long after it has passed the minimum, so it overshoots back and forth and the loss oscillates forever instead of converging (in a real network this usually blows up outright). This is one of the most common real-world PyTorch bugs, and now you'll recognize it instantly.
