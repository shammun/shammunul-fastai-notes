Convolution: stride shrinks, filters multiply

A single conv(1, 4) does two unrelated things at once. Stride controls how far the 3×3 kernel jumps, which sets the output size. The number of filters controls how many feature-map channels come out. Drag the kernel, toggle the stride, and watch the output grid fill in.

The orange square is the 3×3 kernel. Each position it lands on writes one output pixel. With stride = 2 it skips every other spot, so a 28×28 input yields a 14×14 output — half the size.

The output-size formula

Channel expansion: 1 → 4 filters

Each filter is its own learnable 3×3 weight grid. Run all 4 over the same input and you get 4 output channels — each a different feature map (edges, curves, textures…). Stride sets the size of each map; the filter count sets how many maps.
Try switching to stride = 1: the kernel visits every position and the output stays 28×28. Stride is the only thing that changed.
