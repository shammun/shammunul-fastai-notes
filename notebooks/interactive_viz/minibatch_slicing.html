Walking through the data: for i in range(0, n, bs)

A toy dataset of n = 200 samples (each square = 1 image). Step through it batch by batch and watch the slice window slide.

batch size bs = 50
current batch current (partial last batch) already trained on not yet seen

Notice two things. First, min(n, i+bs) protects the last batch: with bs = 60, the final slice is [180:200] — only 20 samples, and that's fine. Second, one full pass over all squares = one epoch. With n = 50,000 and bs = 50 the real loop makes 1,000 weight updates per epoch — that's the whole point of minibatches: many small, frequent updates instead of one giant one.
