What .features really is — the schema & the label decoder

Every sample has named fields with types. The label is stored as a plain integer to save space; a ClassLabel remembers the human-readable names. Click a class on the left, or spin the dial on the right, to see int2str translate 9 → "Ankle boot".

The schema features
{'image': Image() ← a PIL image
'label': ClassLabel(names=[…10…]) ← an int 0–9}
# the ClassLabel carries the int→name mapping
featy = ds.features['label']
featy.int2str(idx)   # single int → name
featy.int2str(yb)    # or a whole list of labels
The decoder int2str
label index = 9
int2str(9) → "Ankle boot"

Why store an int and not the string? Because 60,000 small integers are far cheaper than 60,000 copies of a word, and the model needs numbers anyway. The names live once, inside the ClassLabel feature, ready whenever you want a human-readable title.
